# Архитектура Watertracker-next

## Карта модулей (пять слоёв)
Каждый модуль — один файл `src/mNN-имя.js` + контракт(ы) из реестра + секция
стенда. Никаких querySelector-водителей через чужие узлы: связи только через
явные вызовы контрактов модуля. Слои читаются снизу вверх: нижние не знают
о верхних ничего.

## Стенд (bench)
Прогон: store-JSON (cup-tracker-v1 + cup-liquid-color-v1) → headless-рендер →
`bench/shots/<tag>.png` + отчёт `bench/reports/<tag>.json`:
- уровень: data-wp, transform лифта;
- слои волны: имя анимации, длительность, статус, сдвиг за 1 s (px/s);
- геометрия кромки по path (getPointAtLength): размах вверх/вниз от ватерлинии
  (WT_HEAD=24), доля плоских точек (детектор «среза»);
- пояс: y1/y2 градиента, число стоп;
- цвета: кромка/пояс/пилюли по пикселям снимка (точечно, по запросу).
Базовая линия снимается с ДОНORA (старый www); модуль принят, когда его числа
равны базовой линии в допуске (размах ±0.5 ед., скорость ±5%, плоскость ≤ той же)
И глаз владельца согласен.

## Предложения на слово владельца (04.11, серьёзный разговор-2)
### П1. Отладчик (рост M18) — принято словом владельца, исполнено M18
Наблюдатель, не участник: продуктовые модули не импортируют отладчик; он читает
состояние и подписывается на шину событий. Состав: паспорт устройства; сырое
состояние и храны; журнал событий (save/миграции/облако/рендеры воды); живые
числа стенда на устройстве (размах кромки, плоскость, фазы слоёв); состояние
реестра модулей; «собрать пакет для партнёра» (JSON-дампы + снимок одним
файлом). Вход скрытый (5 тапов по «Версия …»). Шина событий и крюки
наблюдателя закладываются с M19. Статус: ждёт слова владельца.
### П2. Отключаемые модули
Модуль сам объявляет optional в карточке реестра (волна, пузырьки, облако,
напоминания, диагностика — опциональны; ядро, журнал, каталог, интерфейс — нет).
Рубильники опциональных живут В ОТЛАДЧИКЕ (полигон, изоляция багов), не в
продуктовых настройках; продуктовые настройки получают только честные
пользовательские тумблеры под контрактами. Вызывающий код опционального модуля
получает null-безопасную заглушку от реестра. Комбинаторика вкл/выкл в продукт
не выезжает. Статус: ждёт слова владельца (голос партнёра: рубильники только
в отладчике).
### Карточка модуля (формат)
имя/файл; слой; контракты C-xxx; флаг optional; события (излучает/слушает);
секция стенда; статус переноса.
### П3. Время уведомлений «мет» — слово владельца 06.11 (памятка, кода нет)
Уведомление вида «Можно выпить хотя бы немного воды / Выпито {drunk} из
{goal} мл» (случай met кривой темпа, m12-pace.js notifyTextsRender +
paceAnchor при whenGoalMet; строки донора settings-ui 923) в ПРОТОТИПЕ
приходит в начале цикла. Слово владельца 06.11 со снимком экрана:
«отложи на память: в прототипе такие уведомления приходят в начале
цикла». Сейчас next шлёт его по якорю темпа без привязки к началу цикла
(скрин: 05:53, «48 мин.», 2450 из 2200 мл). Выравнивать время этого
семейства уведомлений по началу цикла — когда возьмём цикл напоминаний
(фаза 2b/3, эволюция M12/M13), отдельным словом владельца; до того код
темпа не трогать.
