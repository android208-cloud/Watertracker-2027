# Watertracker-next — Водомер, встроенный заново

Решение владельца 04.11: старое приложение (`android208-cloud/Watertracker`,
ветка остановлена на APK v158) остаётся **донором спеки и продом до приёмки**,
новая кодовая база строится как **конструктор**: каждая функция — отдельный
модуль со своим контрактом и своим доказательством.

## Устав проекта
1. Модуль = контракт (словами, `docs/contracts.md`) + код + стенд-доказательство.
   Нет контракта — нет кода. Нет зелёного стенда — нет выдачи владельцу.
2. Старый код — справка, не фундамент: при переносе функции выписывается её
   контракт из старого кода и backlog, затем доказывается равенство
   (стенд-числа + глаз владельца).
3. Полигон: любой новый механизм сначала живёт в стенде (store-JSON → снимок +
   числа) и только потом предлагается в продукт.
4. Заморозка донора: в старую ветку до конца переезда идут только критичные
   баг-фиксы по слову владельца.
5. Данные владельца священны: локальные ключи и формат облачной копии
   (watercat-24 + lc) переносятся байт-совместимо; откат на донор всегда возможен.
6. Визуальный язык — прежний, пока не родилась идея анимированного интерфейса
   (контракт C-022). Сначала равенство, потом красота.
7. Процессионные правила наследуются: контракты словами до кода; доказательства
   из точных байтов сборки; сборка ДО push; единственный текущий APK; имя APK =
   versionCode; служебные каталоги (shots/, apk/, uploads/ и т.п.) вне коммитов.
8. Единственный тестер продукта — владелец. Партнёр (агент) имеет право голоса
   по архитектуре и процессу. Думать и отвечать — по-русски.

## Каталог
- `docs/contracts.md` — реестр контрактов (C-xxx), выстраданные решения.
- `docs/architecture.md` — карта модулей (Mxx), спецификация стенда, порядок переноса.
- `bench/` — стенд: прогон headless по store-JSON, снимок + числа; отчёты в `bench/reports/`,
   снимки в `bench/shots/` (вне коммитов).
- `src/` — модули новой базы (появляются по мере переноса, каждый со своим файлом).
